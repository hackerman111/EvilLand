# Строгий режим фокуса

`focus_guard` — необязательное булево свойство окна, по умолчанию `false`.
Его нужно включать на активном нативном Wayland-окне. XWayland не поддерживается.
Существующее поведение `preserve_previous_focus` без этого свойства сохраняется.

Когда режим включён:

- Активное окно, его оформление, история фокуса и `hyprctl activewindow` остаются привязаны к защищённому окну.
- Клавиатурный ввод можно передать другому нативному Wayland-клиенту, если его окно плавающее, находится на том же рабочем столе и мониторе, а свойства `hide_from_screen_share` и `preserve_previous_focus` включены.
- Защищённый клиент сохраняет Wayland keyboard enter и XDG activated; клавиши получает только выбранный получатель ввода.
- Обычные окна и layer-shell поверхности не могут забрать клавиатурный фокус. Новые клавиатурные grabs отклоняются.
- Блокируются смена рабочего стола защищённого монитора, переключение специального рабочего стола, смена активного монитора, перенос защищённого окна, изменение его геометрии и состояния fullscreen, переключение floating.
- При закрытии или unmap отдельного получателя, отключении его необходимых свойств или отключении `focus_guard` ввод возвращается защищённому окну.
- Закрытие защищённого окна освобождает режим. Настоящий session lock имеет приоритет и снимает удержание фокуса.

Это управление вводом и состоянием окна, а не граница безопасности или скрытие от операционной системы. SeatManager, Wayland-сокеты, compositor logs и процессы сохраняют сведения о реальном получателе ввода. `hyprctl clients` по-прежнему показывает существующие окна. Приоритет планировщика ОС не изменяется.

## Хоткеи пользовательского конфига

В пользовательский `hyprland.lua` добавлены следующие сочетания. Эта сборка использует Lua-конфиг; старый `hyprland.conf` в установку не входит.

| Сочетание | Действие |
|---|---|
| Super+Shift+G | Включить / выключить строгий режим на активном окне. Перед включением выставляется compositor fullscreen. При выключении окно остаётся fullscreen. |
| Super+Ctrl+V | Подготовить уже запущенный Telegram: исключить из захвата, включить сохранение предыдущего фокуса, сделать плавающим, перенести на рабочий стол активного окна и передать ему ввод. |
| Super+Ctrl+B | Вернуть ввод активному защищённому окну, сохранив строгий режим. |
| Super+Shift+V | Прежний переключатель исключения активного окна из захвата. |
| Super+V | Прежний переключатель floating; защищённое окно игнорирует его до выключения режима. |

Порядок использования: активировать браузер, нажать Super+Shift+G, затем Super+Ctrl+V. Вернуть клавиши браузеру можно сочетанием Super+Ctrl+B или кликом по открытой области браузера. Telegram остаётся на рабочем столе браузера после возврата ввода. Перед обычной работой с другими окнами и меню выключить режим через Super+Shift+G.

Для этой версии требуется перезапуск сеанса с установленным новым бинарником; `hyprctl reload` обновляет конфиг, но не код композитора.

## Границы действия

| Наблюдение | Что обеспечивает режим |
|---|---|
| Alt+Tab, обычный клик по другому окну | Обычная смена активного окна отклоняется. Допустимое скрытое окно получает ввод с сохранением фокуса защищённого клиента. |
| Два окна, плавающий Telegram поверх браузера | Нативный браузер сохраняет keyboard focus / activated. Исключение пикселей отдельного окна выполняет существующее `hide_from_screen_share`. |
| Переключение рабочего стола / активного монитора | Переход с защищённого рабочего стола и смена активного монитора отклоняются. |
| Compositor fullscreen и изменение размеров окна | Состояние и геометрия защищённого окна удерживаются. |
| Fullscreen API страницы, переключение вкладки, навигация, браузерные сочетания | Не блокируются. Браузер управляет DOM, видимостью вкладки и своим интерфейсом самостоятельно. |
| Курсор, pointer leave, клики вне области страницы | Не скрываются и не подменяются. Сохранение keyboard focus не исключает такие наблюдения. |
| Второй монитор, реальные параметры screen / output | Не скрываются. Подключение, отключение и изменение конфигурации устройств не покрыты гарантией режима. |
| `displaySurface`, параметры и размеры capture stream | Не подменяются. Выбранная область захвата остаётся настоящей. |
| Остановка PipeWire / browser capture, завершение track | Не предотвращаются и не маскируются. |
| Падение браузера, закрытие окна, блокировка или завершение сеанса | Постоянство фокуса не гарантируется; session lock сохраняет штатную защиту сеанса. |

Незаметность для ProctorEdu не гарантируется. Производитель описывает дополнительные наблюдения за курсором и действиями вне тестовой области в [релизе 4.16](https://proctoredu.ru/blog/reliz-416-obnovleniya-v-sisteme-proctore).

## Проверки

Интеграционные проверки находятся в `hyprtester/src/tests/clients/private-focus.cpp`.
Они проверяют доставку клавиш, счётчики Wayland focus/activation, IPC, запреты переключений и геометрии, выключение режима, закрытие и unmap окон.
Заключительный прогон: 22/22 проверки прошли, включая прежние случаи сохранения фокуса и проверки клавиатурных модификаторов.

Локальный harness `build/focus-tests/guard-browser-test.py` использует отдельный профиль LibreWolf и отдельный вложенный compositor. Он проверяет DOM focus/blur/visibility/viewport, клики, отрицательный контроль после выключения режима и исполнение трёх реальных Lua bindings. Это не проверка ProctorEdu и не испытание всех браузеров или всех capture backends.
Вместо Telegram в harness используется тестовый Wayland-клиент с appID `org.telegram.desktop`; внутренние диалоги настоящего Telegram отдельно не проверялись.
Проверка прошла: после включения режима фокус и размеры страницы сохранялись при передаче ввода и возврате; выключение режима позволило получить обычный `blur`.

При предложении нового параметра upstream потребуется отдельное обновление wiki. Взаимодействие с Hypr GitHub выполняет пользователь с учётом [AI policy](https://github.com/hyprwm/.github/blob/main/policies/AI_USAGE.md) и [issue guidelines](https://wiki.hypr.land/contributing-and-debugging/issue-guidelines/).
